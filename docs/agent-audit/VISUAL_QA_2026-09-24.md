# Visual QA findings — inspected, not inferred

Inspected with Chromium screenshots at 1440×1000 and 375×812 using the Supabase-free gallery, in both light and dark modes.

## Findings

- Light mode is coherent but intentionally low-contrast in its elevation; nested neutral wells are still distinguishable without adding a blue cast.
- Dark page, card, permanent-brand, status, table, and mobile surfaces preserve hierarchy and readable text.
- Semantic success/warning/danger/info dark surfaces remain distinguishable without neon saturation.
- Filled primary controls remain readable in dark mode.
- The initial dark inspection exposed a real defect: `.glx-inset` had a light fill hardcoded inside a Tailwind custom utility, making fields appear bright gray in dark mode.
- The first attempted semantic variable was still declared inside `@theme`; Tailwind inlined its light value at build time. The final correction uses the runtime-only `--ui-inset-fill` variable outside `@theme`, with separate light and dark resolved values.
- The 375 px capture showed controls wrapping without horizontal page overflow, status cards stacking correctly, and the 320 px test frame remaining contained.
- The dense table uses controlled horizontal behavior/prioritized columns in the gallery; production table patterns still require page-by-page verification.

## Remaining visual QA

The gallery verifies shared primitives and token behavior, not every Supabase-backed production page. Dashboard, full exam-taking, grading, Questions, Students, Profile, dialogs, and drawers still require fixture coverage or authenticated browser review before the target viewport matrix can be marked complete.
